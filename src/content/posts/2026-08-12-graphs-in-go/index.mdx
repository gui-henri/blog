Many fields of modern technology, including AI, have borrowed ideas from a simple mathematical structure: the graph. This note is about how one can be constructed in Go and visualized using Raylib. The goal is to create a simple foundation that can be built upon until we arrive at a robust library capable of representing and implementing neural networks.

## What is a Graph

Visually, a graph can be represented like the image below:

![Simple Graph](http://blog.guigas.com.br/graph.png "Simple Graph")

In its most basic form, a graph is just a collection of nodes and edges, represented by the following formula:

$$
G = (V, E)
$$

Where $V$ represents the nodes (or vertices) and $E$ represents the edges connecting the nodes. An edge can be represented as $\{v_1, v_2\}$. For our case, a node can have any property associated with it.

## The (very) simple implementation of a Graph

There are many ways of implementing a graph, but for the sake of simplicity, we will only use simple structs:

```go
type Node struct {
  label string
  edges []Edge
  data  map[string]any
}

type Edge struct {
  to *Node
}

type Graph struct {
  nodes map[string]*Node
}
```

See that the graph itself is a set of nodes, and the nodes contain a list of edges pointing from them to other nodes. This comes with trade-offs (a node doesn't know the edges pointing to itself, and because `nodes` is a set, it will be harder to iterate over it), but it also has a relatively low memory footprint.

Note that we also have `label` and `data` fields on the node, which hold metadata about it. `label` is the key of the node in the `nodes` map inside `Graph`, and it is stored so we can easily reference it. For any other type of data, we store it in its own separate map, so the node can hold any value. Some functions to easily create graphs, their nodes, and their nodes' edges were also created.

## Example of application

Using Raylib, we can create a bare-minimum application that draws the graph. Initially, a graph was created, and two nodes with random positions, colors, and speeds were added to it. We also added an edge coming from the first node to the second.

```go
g := Graph{}

InitRandomNode(&g, "n1", defaultRadius, maxSpeed, minSpeed, colors)
InitRandomNode(&g, "n2", defaultRadius, maxSpeed, minSpeed, colors)

g.CreateEdge("n1", "n2")
```

Then we convert the set into a list. This is done to keep a consistent drawing order later. Since Go map ordering is random, ranging over a map with a simple `for` loop would not be consistent.

```go
for _, v := range g.nodes {
    // drawNode(v)
}
```

> The code above could output `["n1", "n2"]` in one frame and `["n2", "n1"]` in another. This can cause the nodes to constantly "switch" which one is on top when they're overlapping.

Next, after some logic to add new nodes when a node collides with the window borders and create an edge to the closest node to the new node, we can finally draw them using Raylib:

```go
rl.BeginDrawing()
rl.ClearBackground(rl.Black)

for _, v := range nodeArray {
    x := v.data["x"].(float32)
    y := v.data["y"].(float32)
    color := v.data["color"].(rl.Color)

    for j := range v.edges {
        e := v.edges[j]
        ex := e.to.data["x"].(float32)
        ey := e.to.data["y"].(float32)

        rl.DrawLineEx(rl.Vector2{X: x, Y: y}, rl.Vector2{X: ex, Y: ey}, 4.0, color)
    }
}

for _, v := range nodeArray {
    x := v.data["x"].(float32)
    y := v.data["y"].(float32)
    color := v.data["color"].(rl.Color)

    rl.DrawCircleV(rl.Vector2{X: x, Y: y}, radius, color)
}

rl.EndDrawing()
```

Note that we first iterate over all edges (which also means iterating over all nodes) and then iterate again to draw just the nodes themselves. This is done because we want the nodes to be on top of all edges, and since the nodes don't know the edges pointing to them, an edge may be drawn after a node, hence being rendered on top of it.
